1) Первым делом, чтобы руками не создавать структуру папок мы это сделаем командной `ansible-galaxy init <имя роли>`
Получаем следующую структуру
```
├── defaults/      # Переменные по умолчанию (самый низкий приоритет)
├── vars/          # Переменные роли (высокий приоритет, переопределяют defaults)
├── tasks/         # Главное — список действий (main.yml)
├── handlers/      # Обработчики событий (перезапуск сервисов и т.п.)
├── templates/     # Шаблоны (.j2 файлы для динамической генерации конфигов)
├── files/         # Статические файлы (копируются "как есть")
├── meta/          # Метаданные (зависимости, автор, поддерживаемые ОС)
├── tests/         # Тесты для проверки роли (обычно test.yml)
├── README.md      # Документация по роли
```

Думаю нам следует разобрать что в каждой из папки храниться и должно храниться, ибо это тоже очень важно, чтобы ты не смотрел на это как на какую-то хуйню непонятную
 Разберём только то что нам пока что нужно
## Краткое назначение:

|Папка|Зачем нужна|
|---|---|
|`defaults`|Значения по умолчанию (легко переопределяются извне)|
|`vars`|Жёсткие переменные роли (менять сложнее)|
|`tasks`|Что делать — основная логика роли|
|`handlers`|Что делать "в конце" (перезапустить nginx после изменения конфига)|
|`templates`|Конфиги с переменными (с расширением `.j2`)|
|`files`|Статические файлы (копируются без изменений)|
|`meta`|От какой роли зависит эта роль, её требования|
|`tests`|Проверка работоспособности (обычно `test.yml` + инвентарь)|

## Главное правило приоритета переменных:

Переменные из `vars/` **переопределяют** переменные из `defaults/`, если они названы одинаково.

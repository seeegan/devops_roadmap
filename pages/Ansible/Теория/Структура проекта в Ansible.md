>Ansible - является иденпотеным. Что это значит?
>Идемпотентность в Ansible — это ==способность модулей выполнять задачи многократно, не меняя конечное состояние системы после первого успешного применения==. Если система уже соответствует заданным требованиям (например, пакет установлен), повторный запуск плейбука (playbook) не внесет изменений, сообщая статус «ok» вместо «changed»

Начнём с небольшой структуры с которой я и буду работать по лабам.

Сначала выведем просто всю структуру, вспомним про удобную команду для вывода древовидной структуру папок `tree`

```
tree practice/ansible/infra
```

Вывод следующий:
```                                       
├── ansible.cfg
├── group_vars
├── inventory
├── production.yml
├── roles
├── stage.yml
└── templates

5 directories, 3 files
```

#### Структура папок
`group_vars` - Cначала нужно почитать это [[Приоритизация переменных в Ansible]](для понимания как происходит приоритизация переменных в Ansible). ->
Тут будем описывать групповые переменные хостов, то есть общие для групп серверов.

`inventory` - В этом каталоге будет описана сама инфраструктура. Какие у нас есть сервера, их ip-адреса и т.п.

`roles` - Тут будут храниться наши роли, с помощью них как раз и происходит сама "магия", грубо говоря будем писать инструкцию для клиента ansible который проходя по ней будет исполнять нужные нам действия указанные в инструкции.

`templates` - шаблоны для конфигов и т.п.

#### Структура файлов
`ansible.cfg` - Конфиг ansible, тут можем указать некоторые настройки, например пользователя по дефолту, его путь до ключа (так как ansible работает по ssh-соединению), путь для log-файла и так далее. Параметров для настройки куча, не вижу смысла всё описывать

`production.yml` - Файл в котором мы можем указать группу хостов из `inventory` и "привязать" к ним нужную роль. Нейминг не сильно важен, ведь при запуске плейбука мы будем указывать конкретный `*.yml` для нужной группы хостов.

`stage.yml` - Различий с `production.yml` нет, точно такой-же файл в котором указываем группу хостов и необходимые роли для выполнения

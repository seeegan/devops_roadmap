
### Для чего нужны скрипты?
Представь что тебе каждый день нужно заходить и выполнять на сервере определенную последовательность действий, или даже на нескольких серверах. Давай подумаем как скоро тебя это заебёт? Я думаю что не долго, поэтому существуют скрипты в Linux, где ты пишешь что должно выполняться последовательно. Скрипт как правило выполняется сверху вниз.

Перед тем как писать скрипт мы разберёмся с одной очень важной темой.

### Переменные окружения и PATH

Кто такие эти ваши переменные окружения и для чего они нужны?
Когда вы входите в систему, оболочка bash создаёт набор переменных окружения (environment variables) - именованные значения, которые доступны всем запускаемым программам.

Чтобы посмотреть переменные заданные в системе вы можете использовать команду `env`.

Вывод будет достаточно длинным, поэтому вот несколько важных переменных:

|Переменная|Описание|Пример значения|
|---|---|---|
|`HOME`|Домашний каталог пользователя|`/home/student`|
|`USER`|Имя текущего пользователя|`student`|
|`SHELL`|Путь к оболочке пользователя|`/bin/bash`|
|`PWD`|Текущий рабочий каталог|`/home/student`|
|`LANG`|Язык и локаль|`ru_RU.UTF-8`|
|`PATH`|Где искать программы|`/usr/local/bin:/usr/bin:/bin`|
|`EDITOR`|Текстовый редактор по умолчанию|`nano`|

Чтобы посмотреть значения конкретной переменной мы используем уже известную команду `echo` только после неё нужно ещё указать имя переменной (не забыв перед этим указать символ `$`)
Пример:
```shell
echo $USER
```
![[Pasted image 20260518235101.png]]

Знак `$` говорит bash: «подставь значение переменной». Без `$` bash воспримет слово `HOME` как обычный текст

### Создание и экспорт переменных

Давай создадим свою первую переменную, по традиции это будет привествие
```shell
GREETING="HELLO WORLD!"
echo $GREETING
```
![[Pasted image 20260519000440.png]]

> **Обратите внимание:** вокруг знака `=` **не должно быть пробелов**. Запись `GREETING = "Привет"`вызовет ошибку — bash решит, что `GREETING` — это команда, а `=` и `"Привет"` — её аргументы.

Переменную мы создали, но прикол в том что как только мы начнём новый сеанс эта переменная просто пропадет, так как мы создавали её только для текущей оболочки.

Итак, чтобы переменная стала доступна дочерним процессам необходимо её экспортировать командой `export'.
```
export GREETING="HELLO WORLD!"
```
![[Pasted image 20260519000954.png]]

Как видишь для примера я залогинился под другим пользователем, переменная осталась. 

### PATH - как система находит команды.
Когда ты вводишь любую команду в терминале система ищет путь до этой команды в переменной `$PATH`.

```shell
echo $PATH

->
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
```

Это значит что любая команда сначала ищется по пути `/usr/local/bin` потом в `/usr/local/bin` дальше в `user/sbin` и `usr/bin` и так далее. Думаю порядок ясен, двоеточие в данном случае объединяет всё с один длинный путь

С помощью команды `which` мы можем узнать путь до команды
```shell
which ls
```
![[Pasted image 20260519003846.png]]

Если программа не находится ни в одном каталоге из PATH, bash выдаст ошибку «command not found». Именно поэтому для запуска скрипта из текущего каталога нужно писать `./script.sh` — текущий каталог `.` обычно не входит в PATH.

### Файл ~/.bashrc

Переменные окружения, заданные в терминале, исчезают при выходе из системы. Чтобы настройки сохранялись, их записывают в файл **`~/.bashrc`** — скрипт, который bash автоматически выполняет при каждом входе в систему.

Вы увидите настройки приглашения командной строки (PS1), алиасы и другие параметры. Если вы добавили что-то в `~/.bashrc`, но изменения не применились, выполните:

```bash
source ~/.bashrc
```

Команда `source` выполняет файл в текущей оболочке, применяя все настройки без необходимости выходить и входить заново.

### Первый скрипт

Давай создадим свой первый простой скрипт
```shell
#!/bin/bash
echo "Hello $USER"
sleep 2
echo "Now you are placed in:"
pwd
sleep 1
echo "Date is:"
date
echo "Happy use linux :)"

```
### Shebang

Первая строка `#!/bin/bash` называется **shebang** (или «шебанг»). Она сообщает системе, какой интерпретатор использовать для выполнения скрипта.

```
#!/bin/bash
││
│└─ путь к интерпретатору
└── специальная последовательность символов (#!)
```

Без shebang система не будет знать, что этот файл нужно выполнять через bash. Всегда начинайте скрипты с этой строки.

Обьявление переменных в скрипте точно такое же как и в обычном терминале, поэтому разбирать это смысла я не вижу.

Наверное единственное что можно отметить что bash не всегда может понять где заканчивается переменная
Пример:
```bash
#!/bin/bash
file="access"
echo "$FILE_log"      # Ошибка! bash ищет переменную FILE_log
echo "${file}_log"    # Правильный вариант
```

### Кавычки

В bash есть два вида кавычек, и они работают **по-разному**:

|Кавычки|Поведение|Пример|Результат|
|---|---|---|---|
|Двойные `"..."`|Раскрывают переменные|`"Привет, $USER"`|`Привет, student`|
|Одинарные `'...'`|Всё буквально|`'Привет, $USER'`|`Привет, $USER`|

```bash
#!/bin/bash

NAME="мир"
echo "Привет, $NAME"    # Привет, мир
echo 'Привет, $NAME'    # Привет, $NAME
```

Правило простое: используйте **двойные кавычки**, когда нужно подставить значение переменной, и **одинарные**, когда нужен текст как есть.

### Подстановка команд

Результат выполнения команды можно сохранить в переменную с помощью `$(...)`:

```bash
#!/bin/bash

TODAY=$(date +%Y-%m-%d)
FILE_COUNT=$(ls ~/wordpress-project | wc -l)

echo "Сегодня: $TODAY"
echo "Файлов в проекте: $FILE_COUNT"
```

```
Сегодня: 2026-03-15
Файлов в проекте: 5
```

Конструкция `$(команда)` выполняет команду и подставляет её вывод вместо себя.

## Аргументы скрипта

Скрипту можно передавать аргументы при запуске — как опции обычным командам:

```bash
./script.sh аргумент1 аргумент2 аргумент3
```

Внутри скрипта аргументы доступны через специальные переменные:

|Переменная|Значение|
|---|---|
|`$0`|Имя самого скрипта|
|`$1`|Первый аргумент|
|`$2`|Второй аргумент|
|`$#`|Количество аргументов|
|`$@`|Все аргументы|

Пример — скрипт, который приветствует пользователя по имени:

```bash
#!/bin/bash

echo "Скрипт: $0"
echo "Привет, $1!"
echo "Передано аргументов: $#"
```

```bash
chmod u+x greet.sh
./greet.sh Евгений
```

```
Скрипт: ./greet.sh
Привет, Евгений!
Передано аргументов: 1
```

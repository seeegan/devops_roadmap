> inode (Index Node) в Linux - это структура данных, файловые системы используют её для хранения иформации о файлах и каталогах. Так как в Linux всё есть `файл` у каждого такого файла каким бы он не является (ссылкой, каталогом, блочным устройством и так далее) есть свой номер inode.

inode содержит в себе метаданные о файле (любом файле) - его размер, дата изменения, права доступа, владелец, время создания. В общем всё что мы видим при вводе команды `ls -la` эту информацию мы получаем из таблицы inode.

> ⚠️ inode не содержит информацию о имени файла и о его содержимом

## Основные понятия

- inode - это уникальный идентификатор (индексный узел) для каждого файла или каталога в системе
- Метаданные - информация о файле, дата изменения, владелец, права доступа, размер и так далее
- Указатели на блоки данных - ссылки на блоки данных на диске, где хранится содержимое файла
> То есть inode не содержит в себе данные помещённые в сам файл, будь это код приложения или обычный текст, эти данные хранятся на блоке диска и inode знает только `адрес` по которому можно найти эти данные

## Важные аспекты
1. Отдельная структура для метаданных и данных: `inode хранит метаданные`, а `фактические данные хранятся в блоках данных на диске `. inode хранит только адрес этих самых данных на блоке данных носителя. Это позволяет эффективно управлять файлами и каталогами

2. Имена файлов и inode: В файловой системе Linux/Unix имена файлов и каталоги хранятся **отдельно** от inode:
	- Имена файлов хранятся в каталогах (directories) и указывают на соответствующие inode
	Это позволяет легко создавать жёсткие ссылки (hard links) - несколько имён файлов могут указывать на один и тот же inode

## Важные моменты

- Ограниченное количество inode: При создании файловой системы выделяется определённое количество inode.
>⚠️ Если все inode заняты, то ни пользователь ни система не смогут создать новый файл, даже если на диске осталось свободное место.

- Резервирование inode: При форматировании файловой системы можно указать процент дискового пространства, который будет зарезервирован для системных нужд и предотвращения полного исчерпания inode

Количество inode зависит от `типа` файловой системы и её настроек при создании. В основном это касается файловых систем типа: `ext3`, `ext4`, `XFS` и других. Параметры для изменения количества inode могут быть заданы при форматировании файловой системы.

### Количество inode по умолчанию

1. `ext4`: По умолчанию файловая система `ext4` создаёт один inode на каждые 16КБ пространства. Этот параметр может быть изменён при создании файловой системы
2. `XFS`: В `XFS` количество inode не фиксируется при создании файловой системы. `XFS` динамически выделяет inode по мере их необходимости
3. `Btrfs`: `Btrfs` также динамически выделяет inode по мере их необходимости и не требует предварительного задания их количества

### Часть 1. Что такое блочное устройство

В Linux системах есть как обычные файловые системы (имеющие физический носитель), так и виртуальные файловые системы (их ещё называют `псевдо файловые системы`). Одна из таких псевдо-файловых систем находятся у нас на операционном столе и сегодня мы разберём её до каждого атома.

### Часть 2. Что такое файловая система

Раздел (`vda1`, `vda2`, `vda3`) - это "кусок диска". Чтобы хранить файлы нужная FS(File System) - файловая система. Это структура которая описывает:
- Где какие файлы лежат
- Кто владелец
- Какие права
- Когда создан/изменён
- Какие блоки заняты, какие свободны

Аналогия: раздел - это пустой, никем не заселённый участок земли. ФС - это город с улицами, домами и адресной книгой - где раписаны все жители, какие квартиры (файлы) им пренадлежат и так далее.

#### Основные ФС в Linux

- **ext4** — стандарт для Linux. Надёжная, проверенная.
    
- **xfs** — для больших ФС, хорошо работает с параллельной записью. Часто в RHEL.
    
- **btrfs** — современная, со снапшотами.
    
- **vfat** — для EFI-разделов, флешек. Совместима с Windows.
    
- **NTFS** — Windows.
    
- **tmpfs** — ФС в оперативной памяти. Живёт до перезагрузки. `/tmp` часто tmpfs.


![[Pasted image 20261011171704.png]]
- `vda1 vfat` — EFI-раздел, должен быть vfat, иначе UEFI не загрузит систему.
- `vda2 ext4` — `/boot`, стандарт.
- `vda3 LVM2_member` — не ФС, это **физический том LVM**. Внутри него — логический том с ext4.

### Часть 3. Что делает mkfs

`mkfs.ext4 /dev/<device>` - создать файловую систему

#### Что происходит внутри

1. **Разметка inode-таблицы.** `mkfs` решает, сколько inode выделить. Это фиксировано при создании ФС. Изменить потом можно, но сложно.

2. **Создание суперблока.** Это главная структура ФС. Хранит: размер ФС, размер блока, количество inode, точку монтирования, состояние (clean/dirty).

3. **Создание корневой директории.** Пустая, но существует.

4. **Резервирование места.** ext4 по умолчанию резервирует 5% места для root — чтобы даже при заполненном диске система могла писать логи.


### Часть 4. Как получить свободное блочное устройство

Идея заключается в том, чтобы создать новый файл и сделать его отдельной файловой системой, та как все разделы моего диска (`vda1`, `vda2`, `vda3`) уже заняты и не могут быть использованы для создания новой файловой системы, ведь это под собой подразумевает форматирование раздела, а на разделах корень, плюс файлы для запуска Linux.

Для создания такой "болванки" которая в последующем будет нашим новым блочным устройством (точнее мы заставим думать Linux что это блочное устройство) мы воспользуемся `loopback` драйвером.

### Что такое loopback на уровне ядра
В ядре Linux есть драйвер `loop`. Это обычный драйвер блочного устройства, как драйвер для SATA-диска или NVMe. Но он делает `необычную вещь`: вместо того чтобы читать/писать на физическое железо, он читает/пишет в **файл**

```
Обычный диск:
  /dev/sda  ←  драйвер SATA  ←  физический диск

Loopback:
  /dev/loop0  ←  драйвер loop  ←  файл на диске
```

Ядро не различает эти случаи. Для него `/dev/loop0` - такое же блочное устройство, как `/dev/sda`. Он может делать на нём `mkfs.ext4`, `mount`, `dd` - всё что угодно.

Ключевая идея: `loopback` - это мост между "файлом как данными" и "файлом как блочным устройством"
> Что такое блочное устройство мы уже разобрали выше.


И так, мы разобрались что такое блочное устройство, оно у нас сейчас недоступно для записи, ведь все разделы нашего физического диска заняты и не могут быть использованы для создания новой файловой системы. На самом деле это хороший кейс, ведь мы сможем разобраться как можно обходить такие моменты и познакомимся с Linux чуть больше.

Сейчас нам нужно создать файл - болванку, который мы потом через драйвер loop будем использовать для записи данных как на блочное устройство. Ядро Linux будет записывать туда данные как на блочное устройство, несмотря на то, что это обычный файл который мы создали своими руками.

Чтобы создать такой файл нам нужно воспользоваться утилитой `dd` - data definition иди data duplicator. В шутку - disk destroyer, потому что если ошибиться с of=, можно сести диск.

```shell
dd if=/dev/zero of=/tmp/disk.img bs=1M count=500
```

`dd` - название самой утилиты, ключевое слово для использования комманды
`if` - input file, `файл из которого мы будем брать поток данных`,  не путать с условием if, это разное
	`/dev/zero` - это специальный файл в Linux. Он бесконечно отдаёт нули (байты со значением 0). Как `/dev/null`, только наоборот.
		- `dev/null` - свалка, принимает всё, ничего не отдаёт
		- `dev/zero` - источник, отдаёт бесконечные нули
			Если хочешь проверить как он работает на тесте, то можно попробовать так:
			 `head -c 10 /dev/zero > somefile.txt`
				 `-c` - флаг для того чтобы указать что мы хотим взять первые 10байт из потока вывода драйвера
				 `/dev/zero` - сам драйвер который мы будем использовать
				 `> somefile` - перенаправляем поток вывода из драйвера 10байт в наш файл
			Чтобы посмотреть что получилось используем утилиту `xxd`:
				`xxd somefile`
				![[Pasted image 20261011205906.png]]
				> Как мы видим это обычный поток байт
				
`of` - output file, файл вывода данных из `if`, `of=<filepath>`
`bs` - block size размер блока данных
`count` - количество блока данных, в нашем случае это 500, значит на выходе файл выйдет на 500Mb.

```shell
bb if=/dev/zero of=/tmp/testfs.img bs=1M count=500
```

Теперь после того как мы создали наше "блочное устройство", создали файловую систему нам нужно её `монтировать`. У большинства понятие монтирование заканчивается на команде `mount`. Но что там происходит когда мы вводим эту команду, какие есть флаги и что вообще значит `монтировать`?

### Монтирование

Проблема которую решает монтирование.
Представь, у тебя есть несколько дисков. Один - с системой (`/`), второй с данными, третий - с бэкапами. Как пользователь должен получить доступ к файлам на втором и на третьем?

Вариант 1: "дай каждому диску отдельную букву (Как в Windows). `C:`, `D:`, `E:`". Просто, но ограниченно.

Вариант 2: "встрой диск в существующее дерево" (как в Linux). Диск прикрепляется к какой-то директории, и его содержимое появляется внутри этой директории. То есть мы подключили диск, и вместо того чтобы как-то помечать его буквами или ещё чем-то - вставляем его в уже существующую папку и уже можно им пользоваться. 
> В нашем примере "вставленный диск" это наш `loop0`. Сейчас у нас есть блочное устройство, файловая система, но пока мы её не видим, её нужно куда-то запихнуть чтобы можно было ей пользоваться.

Так вот Linux выбирает второй путь. Это и есть монтирование, то есть помещение диска в уже существующую папку, при этом отдельный том (как в Windows) не создаётся (ну за исключением нашего случая,  тут мы сами создали диск и "подключили его", если бы мы просто взяли внешний SSD и подключили он бы просто отобразился в /dev/devicename и мы могли бы сразу использовать его для создания и монтирования FS.), а просто помещается в директорию.

## Ключевая идея

В Linux **всё — единое дерево**, начинается с `/`.
```
/
├── bin/
├── etc/
├── home/
├── var/
└── mnt/
```
Когда ты **монтируешь** диск в `/mnt/data`, содержимое этого диска **подставляется** в `/mnt/data`. Точка `/mnt/data` становится «входом» на другой диск.

**Аналогия:** это как дверь. Пока дверь закрыта — за ней просто стена (пустая директория). Открыл (смонтировал) — за дверью целая комната (содержимое диска). Закрыл (размонтировал) — снова стена.

```shell
sudo mount /dev/loop0 /mnt/testfs
```
`mount` - команда для монтирования
`/dev/loop0` - указываем какое блочное устройство мы хотим поместить в существующую папку
`/mnt/testfs` - заранее нужно создать директорию иначе будет ошибка что такая точка монтирования не найдена `sudo mkdir /mnt/tesfs`

#### Важный нюанс
> ⚠️Если мы до того как монтировали FS в нашу директорию `/mnt/testfs` поместили туда какой-то файл, допустим это будет `test1.txt`, то после монтирования этого файла мы не увидим, он скажем так "спрячется", поэтому важно, не помещать туда какие-то нужные файлы до монтирования, эти файлы вы не увидите после монтирования. Увидеть их можно будет только если вы размонтируете её (`umount`) и после этого они снова отобразятся.



У нас есть блочное устройство, файловая система которая уже смонтирована в `/mnt/testfs`, теперь можем посмотреть что такое inodes вживую, попробуем забить диск мелкими файлами, они будут весить меньше 4КБ, но мы специально забьём inode до краёв и посмотрим что произойдёт.

Для этого можем написать небольшой скрипт который создаст большое количество файлов в нашем новом диске.

Для начала убедимся что он есть и посмотрим сколько на нём inodes.
```shell
di -i /dev/loop0
```

> Свободных 127988 inodes

Теперь давайте их забьём
```shell
sh for i in {1..128000}; do touch file$i.txt done
```

> После того как скрипт отработал, мы видим что диск занят всего на 2%, но новый файл создать мы не сможем так как inodes просто закончились. Это самый наглядный способ увидеть что такое Inode и почему плохо когда они заканчиваются.

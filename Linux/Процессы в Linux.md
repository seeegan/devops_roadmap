### Понятие процесс
Давай попробуем разобрать что такое процесс в Linux. При вводе любой комманды (за пример возьмём `ls` ) у нас запускается процесс. В зависимости от запущенной программы она либо сразу завершается (то есть передаётся сигнал SIGTERM), либо ждёт своего завершения (например `top`). Во всех случаях создаётся процесс имеющий свой уникальный `PID` (process id). 
Процессы образуют **дерево**: каждый процесс (кроме самого первого) создан другим процессом — **родительским**. Самый первый процесс в системе имеет PID 1 — это **systemd**, о котором мы подробно поговорим ниже.

### Просмотр процессов
`ps` - снимок процессов
Команда с помощью которой можем посмотреть текущие запущенные процессы  в системе
Стандартный набор флагов с которыми данная команда запускается
```bash
ps aux
```

|Флаг|Значение|
|---|---|
|`a`|Показать процессы всех пользователей|
|`u`|Показать подробный формат (пользователь, CPU, память)|
|`x`|Показать процессы без терминала (демоны, сервисы)|
При выводе данной команды у нас отображается слишком много строк по которым просто неудобно искать нужный нам процесс. Используй в сочетании с командой следующую запись
```bash
ps aux | grep <имя процесса>
```

Так как мы уже научились работать со строками в linux, можем как-то интересно отсортировать вывод команды `ps` ведь он выдаёт нам в результате нечто иное как строки.
```bash
ps aux | grep vscode | awk '{print "process id is:" $2}' | sort -rn | uniq -c
```

OUTPUT:
```shell
   1 process id is:35747
   1 process id is:35653
   1 process id is:35633
   1 process id is:35632
   1 process id is:35537
   1 process id is:35531
   1 process id is:2290
```

Основные столбцы вывода `ps aux`:

|Столбец|Значение|
|---|---|
|`USER`|Владелец процесса|
|`PID`|Идентификатор процесса|
|`%CPU`|Использование процессора|
|`%MEM`|Использование памяти|
|`COMMAND`|Команда, которой запущен процесс|
### pstree — дерево процессов

Чтобы увидеть иерархию процессов (кто кого породил):

```bash
pstree
```

С отображением PID:

```bash
pstree -p
```

### top — интерактивный мониторинг

Команда `top` показывает процессы в реальном времени — как «Диспетчер задач» в Windows. Информация обновляется каждые несколько секунд:

```bash
top
```

Полезные клавиши внутри `top`:

|Клавиша|Действие|
|---|---|
|`q`|Выйти|
|`k`|Завершить процесс (спросит PID)|
|`M`|Сортировать по памяти|
|`P`|Сортировать по CPU|
|`1`|Показать все ядра процессора|

> **htop.** Существует улучшенная версия — `htop`, с цветным интерфейсом и более удобным управлением. Если хотите попробовать, установите её: `sudo apt install htop`. Для нашего курса достаточно стандартного `top`.


## Управление процессами

### Сигналы

Чтобы повлиять на работающий процесс (остановить, перезапустить), ему отправляют **сигнал**. Самые важные:

|Сигнал|Номер|Описание|
|---|---|---|
|`SIGTERM`|15|Вежливая просьба завершиться. Процесс может сохранить данные и выйти корректно|
|`SIGKILL`|9|Принудительное завершение. Процесс не может его проигнорировать|
|`SIGHUP`|1|«Перечитай конфигурацию». Многие сервисы перезагружают настройки без перезапуска|

### kill — отправка сигнала
```bash
kill 1234          # отправить SIGTERM процессу с PID 1234
kill -9 1234       # отправить SIGKILL (принудительное завершение)
kill -HUP 1234     # отправить SIGHUP (перечитать конфигурацию)
```

>Всегда начинайте с `kill` (SIGTERM) — дайте процессу завершиться корректно. Используйте `kill -9` только если процесс не реагирует на обычный `kill`.

### Фоновые процессы

Когда вы запускаете команду в терминале, она занимает его до завершения. Но можно запустить команду **в фоне**:

```bash
sleep 60 &
```

Символ `&` в конце запускает команду в фоновом режиме. Терминал остаётся свободным.

Полезные клавиши и команды:

|Действие|Команда|
|---|---|
|Прервать текущий процесс|`Ctrl+C` (отправляет SIGINT)|
|Приостановить текущий процесс|`Ctrl+Z` (отправляет SIGTSTP)|
|Посмотреть фоновые задачи|`jobs`|
|Вернуть задачу на передний план|`fg`|
|Продолжить задачу в фоне|`bg`|


### systemd

Пожалуй очень важная и фундаментальная тема это systemd. Это первый процесс который запускается в Linux и от него уже идут дочерние процессы. В этом разделе мы разберемся как с ним взаимодействовать и что он вообще может.

Ранее мы разбирали процессы у которых цель выполнить действие -> дождаться сигнала о завершении -> завершить свою работу. Но помимо обычных процессов есть и такие которые должны выполняться постоянно, например NGINX-сервер или же если он вдруг упадёт то нужен помощник который его поднимет самостоятельно. Думаю понятно к чему я клоню, таким помощником и является systemd. 

systemd — это тот самый процесс с PID 1, корень дерева процессов. Он запускается ядром первым и затем поднимает всю остальную систему: монтирует диски, настраивает сеть, запускает сервисы.

Каждый объект, которым управляет systemd, называется **юнитом** (unit). Юниты бывают разных типов:

|Тип|Расширение|Описание|
|---|---|---|
|Сервис|`.service`|Программа-демон (nginx, sshd, cron)|
|Таймер|`.timer`|Запуск задач по расписанию (замена cron)|
|Сокет|`.socket`|Активация сервиса при подключении к порту|
|Точка монтирования|`.mount`|Монтирование файловой системы|
|Цель|`.target`|Группа юнитов (аналог «уровня запуска»)|

Чаще всего вы будете работать с типами `.service` и `.timer`.

### systemctl - управление сервисами
`systemtctl` - главная команда для работы с `systemd`. Рассмотрим её на примере сервиса SSH, который уже работает в нашей системе.
```bash
systemctl status ssh
```
![[Pasted image 20260512211205.png]]
Ключевые строки:

|Строка|Значение|
|---|---|
|`Loaded: loaded (...; enabled)`|Юнит загружен; **enabled** — запускается автоматически при загрузке|
|`Active: active (running)`|Сервис работает прямо сейчас|
|`Main PID: 654`|PID основного процесса|

### Запуск, остановка, перезапуск
```bash
sudo systemctl start ssh       # запустить сервис
sudo systemctl stop ssh        # остановить сервис
sudo systemctl restart ssh     # перезапустить (stop + start)
sudo systemctl reload ssh      # перечитать конфигурацию без перезапуска
```
>**restart vs reload.** `restart` полностью останавливает и запускает сервис заново — клиенты на секунду теряют связь. `reload` просит сервис перечитать конфигурацию «на лету», без остановки. Не все сервисы поддерживают `reload` — если не поддерживает, команда вернёт ошибку.

### Автозапуск при загрузке

```bash
sudo systemctl enable ssh      # включить автозапуск
sudo systemctl disable ssh     # отключить автозапуск
```

`enable` не запускает сервис прямо сейчас — только добавляет его в автозагрузку. Чтобы сделать и то, и другое одной командой:

```bash
sudo systemctl enable --now ssh
```

### Список сервисов

Посмотреть все загруженные сервисы:

```bash
systemctl list-units --type=service
```

Только активные (работающие):

```bash
systemctl list-units --type=service --state=running
```

## journalctl: чтение логов

systemd ведёт централизованный журнал — все сообщения от всех сервисов собираются в одном месте. Читать этот журнал можно командой `journalctl`.

### Логи конкретного сервиса

```bash
journalctl -u ssh
```

Флаг `-u` (unit) фильтрует записи по имени юнита.

### Последние записи

```bash
journalctl -u ssh -n 20        # последние 20 строк
```

### Следить в реальном времени

```bash
journalctl -u ssh -f
```

Флаг `-f` (follow) работает как `tail -f` — показывает новые записи по мере их появления. Выход — `Ctrl+C`.

### Фильтрация по времени

```bash
journalctl -u ssh --since "2026-03-16 10:00"
journalctl -u ssh --since "1 hour ago"
journalctl -u ssh --since today
```

> **Подробнее о логировании.** В этой главе мы рассматриваем `journalctl` как инструмент диагностики сервисов. Полноценный разбор логирования и мониторинга — в главе 12.


## Устройство unit-файла

Мы научились управлять сервисами снаружи. Теперь заглянем внутрь — посмотрим, как описан сервис.

### Где хранятся unit-файлы

Unit-файлы лежат в нескольких каталогах:

|Каталог|Назначение|
|---|---|
|`/lib/systemd/system/`|Файлы, установленные пакетами (nginx, ssh, cron)|
|`/etc/systemd/system/`|Файлы, созданные администратором (имеют приоритет)|

Посмотреть содержимое unit-файла можно командой:

```bash
systemctl cat ssh
```
![[Pasted image 20260512212905.png]]
Хотелось бы разобраться за что отвечает тут каждая строчка

Разберём по секциям:

**Секция [Unit]** — общее описание:

|Директива|Значение|
|---|---|
|`Description`|Человекочитаемое описание сервиса|
|`Documentation`|Ссылка на документацию|
|`After`|Запускать после указанных юнитов (здесь — после настройки сети)|

**Секция [Service]** — как запускать и контролировать:

|Директива|Значение|
|---|---|
|`Type`|Тип сервиса (`notify`, `simple`, `oneshot`, `forking`)|
|`ExecStartPre`|Команда перед запуском (здесь — проверка конфигурации)|
|`ExecStart`|Основная команда запуска|
|`ExecReload`|Команда для `systemctl reload` (перечитать конфигурацию)|
|`Restart`|Когда перезапускать (`on-failure` — только при сбое)|

**Секция [Install]** — автозапуск:

|Директива|Значение|
|---|---|
|`WantedBy`|К какой цели (target) привязать при `systemctl enable`|

> **Что такое multi-user.target?** Это цель, которая соответствует обычному режиму работы сервера (многопользовательский режим с сетью, но без графического интерфейса). Большинство серверных сервисов привязываются именно к ней.

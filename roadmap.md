# DevOps Roadmap — Сергей Ганин

> Цель: получить оффер DevOps / Cloud Platform Engineer в Армении или удалённо.
> Режим: 10–15 часов в неделю минимум, 20+ часов — ускоренный.
> Горизонт: 8 недель подготовки + параллельный поиск.
> Реалистичный срок до оффера: 2–3 месяца при регулярных откликах и собеседованиях.

---

## 0. Главные принципы

- **70% качества, опубликовано, можешь объяснить — достаточно.**
- Не делай идеальную структуру до результата. Сначала результат, потом рефакторинг.
- Один файл на неделю. Не создавай 20 папок.
- Таймбокс: 90 минут на задачу. Не готово — фиксируешь текущее и идёшь дальше.
- README проекта — максимум 1 экран.
- Не переделывай структуру, пока не набрал 20 заметок.
- Разреши себе черновик. «Черновик сегодня» лучше «идеала через месяц».
- Не жди полной готовности. Начинай откликаться через 2–3 недели.
- Собеседования — лучший тренажёр. Ошибки = обратная связь.

## 3. Ориентировочные сроки


| Этап                           | Длительность | Что на выходе                                           |
| ---------------------------------- | ------------------------ | ------------------------------------------------------------------ |
| База + Docker/CI/CD            | Недели 1–2        | Linux runbook, Dockerfile, CI-пайплайн                     |
| Kubernetes + Helm + GitOps         | Недели 3–4        | Приложение в K8s, Helm chart, ArgoCD                    |
| Мониторинг + IaC + Cloud | Недели 5–6        | Дашборды, алерты, Terraform, Ansible                 |
| SRE + Security + Capstone          | Недели 7–8        | Capstone, mock-интервью, слабые темы             |
| Активный поиск        | Недели 3–12       | 5–10 откликов в неделю, собеседования |

**Итого:**

- **8 недель** — базовая подготовка и capstone.
- **С 3-й недели** — активные отклики.
- **2–3 месяца** — реалистичный срок до оффера при 10–15 ч/нед.
- **6–8 недель** — если 20+ ч/нед и быстро проходишь собеседования.

## 4. План на 8 недель

**Теория:**

- Процессы, systemd, journalctl, df/du, top/htop, ss, tcpdump, dig, curl.

- TCP/IP, DNS, HTTP/HTTPS, TLS, NAT, балансировка.

**Практика:**

- Linux troubleshooting runbook: disk full, systemd, logs, DNS, tcpdump.

**Результат:**

**Вопросы:**

- Disk full — что смотреть?
- DNS не резолвится — как проверить?
- Сервис не стартует — твои действия?

### Неделя 2. Docker, CI/CD

**Теория:**

- Namespaces, cgroups, слои, volumes, networks, Dockerfile.
- CI/CD: stages, artifacts, cache, secrets, runners, webhooks.

**Результат:**

- Пайплайн в репозитории.

**Вопросы:**

- Как уменьшить размер образа?

**Вопросы:**

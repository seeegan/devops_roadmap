## Что разобрал

### 1. Процессы

- Программа vs процесс:
> Программа - это просто бинарник в каталоге, интрумент, утилита. А процесс это запущенная программа, у неё есть `PID`,`PPID`,`USER`, ресурсы затраченные на выполнение программы
- PID, PPID, UID, GID:
> `PID` - process id, целое число означающее идентификатор процесса, `PPID` - parent process id, точно такое же целое число, означающее идентификатор родителя процесса.
- fork() и exec():
> `fork()` - при создании процесса вызывает `syscall` `fork()` , что означает "скопируй структуру текущего процесса и породи новый", при создании нового процесса ему присваивается новый `PID` и `PPID` - который будет являться процессом который его породил, то есть кто вызывает `fork()` - тот и становится родителем. `exec()` - системный вызов который заменяет текущую программу процесса на другую, при этом не наследуются обработчики, наследуются только игнорирования сигналов
- Команды: `ps aux`, `ps -ef`, `top`, `htop`:
> `ps aux` - стандартный набор флагов для просмотра всех процессов в системе и всех демонов. `ps -ef` - флаг `-e` показать все процессы в системе, `-f` стандартный формат, через флаг `-o` можно указать поля которые мы хотим видеть. `top` - программа которая показывает нагрузку системы в реальном времени, `htop` - тоже самое, только более продвинутый вариант

### 2. Состояния процессов (STAT)

| Код | Что значит                                                                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R   | Running (запущенный процесс, потребляющий `CPU`)                                                                                                                                    |
| S   | Sleeping (большая часть процессов в этом состоянии), спит, ждёт завершения или отработки дочерних процессов                                                                         |
| D   | D-state, статус который показывает какие процессы ждут `I/O` , то есть пока прочитается/запишется информацию на диск. В таком статусе процесс убить нельзя даже через `SIGKILL -9`. |
| Z   | Zombie, статус для ребёнка, когда он отработал, вызвал `exit(code)`, передал свой `exit code` но родитель ещё пока не вызвал `wait()`.                                              |
| T   | Stopped, остановленный процесс, процесс на который был отправлен сигнал `SIGSTOP` (ctrl + z в терминале например). Он не завершён, его можно продолжить через тот же `fg`.          |

- Дополнительные флаги (`s`, `l`, `<`, `N`, `+`):
`s` - Sesson leader
`l` - Multi - threaded
`<` - Высокий приоритет (`nice < 0)
`N` - Низкий приоритет (`nice > 0`)
 `+` - В foreground

### 3. Сигналы

| Сигнал  | Номер | Что значит                                                              |
| ------- | ----- | ----------------------------------------------------------------------- |
| SIGHUP  | 1     | Подается при отключении терминала все процессам, или "перечитай конфиг" |
| SIGINT  | 2     | ctrl + c в терминале, завершение процесса                               |
| SIGKILL | 9     | Жёстко завершить процесс                                                |
| SIGTERM | 15    | Мягкое завершение процесса                                              |
| SIGSTOP | 19    | Остановить процесс, поставить его на паузу                              |
| SIGCONT | 18    | Продолжить процесс                                                      |

- Разница SIGTERM vs SIGKILL:
>`SIGTERM` - сигнал 15, мягко завершает процесс, даёт ему выполнить действия (если такой обработчик есть) и после чего завершает, его можно обработать, а значит перехватить и передать управление программе, которая сделает все свои дела и потом уже завершиться. `SIGKILL` - сигнал 9, жёсткое завершение процесса, быстро и бескомпромиссно
- Что значит «обработать сигнал»:
> Например вместо обычного `SIGTERM` для процесса выполнится его функция, которая сохраняет какие-то данные в лог-файл, делает какой-то чекап и только потом завершается. Значит вместо "мягкого завершения" - выполни определённый алгоритм и только потом завершайся.
- `kill -l`:
> `-l` - list, то есть список всех сигналов с номерами которые могут быть отравлены через программу `kill`.

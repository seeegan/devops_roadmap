## Что я знал до начала

Inode — это метаданные файла. Монтирование — это подключение ФС к дереву. Но не мог объяснить точно, чем inode отличается от file descriptor, и почему «диск полный, а du пустой».

---

## Что разобрал

### 1. Слои абстракции

```
Диск            /dev/vda
  └── Раздел    /dev/vda1, vda2, vda3
      └── ФС    ext4, xfs, vfat
          └── Точка монтирования  /mnt/testfs
```

### 2. Inode

- Структура метаданных файла на диске
- Хранит: права, владельца, размер, timestamps, указатели на блоки
- НЕ хранит: имя файла, содержимое
- Один inode — много hard links
- Команды: `ls -i`, `stat`, `df -i`
- **Важно:** ext4 создаёт 1 inode на каждые 16 КБ

### 3. File descriptor

- Число в таблице процесса, ссылка на открытый файл
- Живёт в памяти ядра, не на диске
- Команды: `ls -l /proc/<PID>/fd`, `lsof`

### 4. Монтирование

- НЕ копирование. Подключение ФС к дереву директорий.
- Данные не копируются, они становятся доступны по пути.
- Команды: `mount`, `umount`, `findmnt`, `lsblk -f`
- `/etc/fstab` — что монтируется при загрузке

### 5. Loopback

- Файл → блочное устройство
- `losetup -fP` — создать вручную
- `mount -o loop` — то же, но в одну команду

## Практика

### Что делал

1. Создал файл-«диск» через `dd if=/dev/zero of=/tmp/testfs.img bs=1M count=500`
2. Создал ФС: `sudo mkfs.ext4 /tmp/testfs.img`
3. Смонтировал через loopback: `sudo mount -o loop /tmp/testfs.img /mnt/testfs`
4. Проверил `df -h` и `df -i`
5. Забил 128000 файлов через цикл
6. Увидел ошибку `No space left on device` при свободном месте
7. Разобрал сценарий «файл удалён, но место занято»
8. Размонтировал, отсоединил loopback, убрал файл

### Ключевой вывод

`df -h` и `df -i` — это **два разных ресурса**. Можно упереться в лимит inode, имея свободное место. Причина — маленькие файлы съедают inode быстрее, чем место.

### Что удивило

Файл `test.txt`, созданный в `/mnt/testfs` до монтирования, стал невидим после монтирования ФС. Данные не потерялись — они скрылись за точкой монтирования.

## Что понял

1. **Inode ≠ file descriptor.** Inode — метаданные файла на диске. fd — ссылка на открытый файл в памяти.
2. **Inode ≠ hard link.** Inode — структура. Hard link — имя в директории, указывающее на inode.
3. **Монтирование ≠ копирование.** Это подключение ФС к дереву.
4. **`No space left on device` может значить «кончились inode», а не место.**
